# PilotHub 0.10.0-alpha.3 Roadmap

状态：Frozen

主题：Native Plugin Invocation 与 L1 收口

## 目标

> 让 PilotHub 根据宿主能力选择可靠的 Plugin 调用入口，并完成 Plugin 全生命周期治理，从 L1 后期进入 L1 完成。

Alpha.3 不扩大 Extension 类型，只收口 Skill-only Plugin。

## 当前起点

Alpha.2 已验证：

- 公共 GitHub Plugin 可以通过 PilotHub 安装；
- 完整 Plugin 可以统一展示和治理；
- Launcher Skill 可以让 Codex Skills 目录和 ChatGPT `@` 菜单发现业务入口；
- 多个 Plugin Skills 可以完成文章、封面和配图任务；
- 内容可以进入微信公众号草稿箱。

当前缺口是：用户可见入口仍默认依赖 Launcher，Native Plugin 能力尚未被独立探测和验证。

## 交付范围

### PR #51：架构冻结

- 定义 Native、Compatibility 和 Unavailable 三种入口模式；
- 定义宿主能力检测规则；
- 冻结安装、诊断、更新、回滚和卸载行为；
- 冻结 Alpha.2 Launcher 迁移策略；
- 明确 L1 完成标准。

交付文档：

- `docs/architecture/native-plugin-invocation.md`
- `docs/roadmap/v0.10.0-alpha.3.md`

### PR #52：Native 能力检测

- 为 Codex/ChatGPT 目标增加结构化能力探测；
- 验证 Plugin 注册、列表、发现和调用边界；
- 记录失败原因，不以客户端版本号代替能力探测；
- 保留 Launcher，不在本 PR 改变现有用户入口。

验收：PilotHub 能可靠回答“当前环境是否可以不依赖 Launcher 调用该 Plugin”。

### PR #53：Compatibility Launcher 条件化

- Native 验证成功时不再创建 Launcher；
- Native 不可用或未验证时继续创建 Launcher；
- 幂等迁移 Alpha.2 已安装 Plugin；
- 保护用户所有的同名 Skill；
- 防止 Native 和 Launcher 重复显示。

### PR #54：生命周期与产品状态

- Doctor 展示 Plugin 注册与入口模式；
- 修复时重新探测并恢复可调用入口；
- 更新、失败回滚和版本回滚保持入口一致；
- 卸载清理 PilotHub 所有的 Plugin 入口；
- UI 使用“原生 Plugin”或“兼容模式”，不再把 Launcher 当作 Plugin。

### PR #55：真实环境验收

使用 `LiYeshu/wechat-content-expert-team`：

```text
从 Alpha.2 状态启动
→ 升级 PilotHub
→ 探测并迁移入口
→ 使用 @微信公众号内容智能体
→ 更新 Plugin 0.1.0 → 0.1.1
→ 完成业务调用
→ 回滚到 0.1.0
→ 再次调用
→ 卸载
→ 验证无残留
→ 重装并最终调用
```

验收覆盖 Codex 与 ChatGPT 当前可用环境；不能自动验证的宿主步骤必须保留人工证据和结果记录。

### PR #56：发布 Alpha.3

- 统一版本号；
- 更新 Changelog 和 Release Notes；
- 运行完整 CI 与跨平台 Release；
- 完成 macOS 真机与 Plugin 冒烟验收；
- 收口 `main` 和 `develop`。

## 不做

Alpha.3 明确不包含：

```text
Assistant Instance
Plugin 配置页
品牌与账号 Profile
记忆层
Workflow Runtime
MCP / Apps
多 Agent Handoff
Marketplace
云端账号与同步
自动正式发布
```

## 发布门槛

- Web 与 Rust 全量检查通过；
- 入口能力判断可解释、可重复；
- Native 不可用时 Compatibility 自动生效；
- Alpha.2 升级不丢失现有调用能力；
- Plugin 更新和回滚后仍能调用；
- 卸载无 PilotHub 所有的残留；
- 真实公众号 Plugin 完成一次端到端调用；
- 产品仍处于 L1，不混入 L2/L3 数据模型。

## 完成后的下一阶段

Alpha.3 完成后，PilotHub 才开始设计 L2 Assistant Platform：

```text
Plugin Definition
    ↓
Assistant Instance
    ↓
独立品牌、账号、素材、配置和凭证
```

L2 必须作为新的架构阶段单独立项，不继续扩入 `0.10.0-alpha.3`。
